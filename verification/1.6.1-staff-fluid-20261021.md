# 1.6.1 手杖周围源流体收集

## 行为

- X → 展开 → 吸取周围流体；默认关闭，默认半径 4 格、每 20 游戏刻最多 4 桶。半径 1～16（以玩家为中心的立方体），速率 1～64 桶/20 刻。
- 主手或副手持杖时运行；同一玩家只运行一把，主手优先。背包中不被持有的手杖不会被动抽水。
- 只处理 `LiquidBlock`、`isSource()`、`LEVEL=0` 且无方块实体的完整源格，一格恰好 1000 mB。水、岩浆和标准模组流体走同一路径；流动、下落、含水方块和储罐不处理。
- 完全复用无用之物 2.4.6 的 `UComponents.WIRELESS_LINK_TARGET`、`AEStoragePriorityComponent` 与公开的 `AE2Compat.resolveLinkedGrid`。在 G 开启“AE 联网模式”后潜行右键无线访问点绑定，再开启“AE 存储优先”。绑定后可以关闭联网交互模式，不影响已保存的绑定及收集。
- 不寻找附近替代网络。没有绑定、绑定节点离线/区块未加载、AE 容量不足 1000 mB 时保留原流体。跨维度绑定仍需目标节点区块已加载。
- 先检查完整一桶容量及玩家权限，再移除源格并向真实 ME 存储服务插入。不可变 `PendingFluid` 数据组件记录部分接收后的余量，具备有界数量、持久化及网络编解码；余量未存完前不再移除其它源格。
- 权限使用可取消的 `BreakEvent` 子类，同时检查世界边界、`mayBuild`、`mayInteract`；标记事件跳过本体的挖掘分发，防止掉落或连锁挖掘副作用。此处测试的是事件取消契约，没有宣称已运行所有领地模组。
- 每玩家每刻最多检查 512 格，全服务器最多 4096 格，轮换玩家并使用约 2 ms 的协作扫描预算；不加载源区块或绑定节点区块。空区域完成一轮后等待 20 刻。单次第三方存储或权限回调不能被预算抢占，实际速率可能低于设置上限。
- 时停、禁止交互的穿墙状态、旁观、死亡和禁止建造状态不收集。外部存储运行异常时暂停该玩家收集 200 刻并保留已记录的余量；这不是跨世界与第三方存储的崩溃原子事务承诺。

## 实际验证

使用 `build/mod-fixture-occultism-full-1.224.4-20261019` 的 26 个外部 JAR，包含无用之物 2.4.6、AE2 19.2.17、Occultism 1.224.4、Ars、Bees、Curios、JDT/JDTE、AE2LT 等。这是兼容性 fixture，不是完整 ATM10/KubeJS 实例。

- `fluid-source-regression-20261021.log`：源格、整桶、真实无线节点与 AE2 1k 流体盘、容量不足、流动/下落/含水、权限取消、部分插入、范围、速率、副手、双持、预算和组件编解码通过。
- `fluid-source-restart-20261021.log`：09:13:20 完成全部服务端检查，包含真实本体潜行绑定事件、下界岩浆存入主世界绑定网络、跨进程恢复已移除源格及物品 NBT 中的 600 mB 余量。容量 999 mB 与“模拟可入一桶但执行只入 400 mB”使用挂到真实 ME 服务上的可控 `MEStorage`，重启时从 fixture NBT 恢复已存 400 mB 和物品余量，总量严格 1000 mB。
- `fluid-guide-client-20261021.log`：09:15:47 的 `STAFF FLUID UI CHECKS PASSED`，普通/320×240 视口、真实滑块拖至 16/64、翻译与滚动检查；`GUIDE CHECKS PASSED` 确认九页编译/渲染及四个物品入口。
- `fluid-packaged-first-20261021.log` 和 `fluid-packaged-restart-20261021.log`：最终生产 JAR 的 672 条目字节保持不变，仅在 build 下诊断副本中追加回归源集。09:17:29 与 09:19:35 两个真实 Java 进程通过同一组检查，第二次确认 `STAFF FLUID REAL RESTART PASSED`。生产条目身份审计见 `fluid-packaged-production-entry-20261021.json`；交付包不含追加测试。
- 截图在 `build/guide-fluid-20261021/screenshots/fluid-settings-{0,1,2}.png`；默认窗口截图已人工查看，说明、绑定状态、滑块及返回按钮无重叠。旧剧情与旧回归证据未覆盖。

开发期曾发现并修复把可变 `FluidStack` 注册为数据组件的问题。初次测试初始化还修正了重复调用 AE `onReady`、水与相邻岩浆发生原生反应的 fixture，以及绑定前未打开本体联网模式的 fixture。滑块测试修正了未拖到原版滑块实际端点的坐标；失败日志保存在 `build/fluid-*-failure-20261021.log`，没有把失败的 Gradle 零退出当作通过。

打包启动配置捕获首次受 Gradle 配置缓存限制失败；关闭配置缓存后重新捕获成功。首次最终包进程使用的既有解析 classpath 与重新捕获结果逐项一致，流体测试开关来自当次生成的 VM 参数。第三方 GuideME 页面有重复索引/缺失图标及 fixture 自带标签警告，保留原始日志，未宣称无警告或完整整合包验证。
