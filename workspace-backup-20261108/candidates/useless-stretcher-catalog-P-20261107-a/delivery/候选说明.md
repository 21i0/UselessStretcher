## 修复内容

目录属于无用之物本体；此候选通过担架内兼容 Mixin 接管其构建调度，保留本体 JAR、原指纹算法、原生 Snapshot 与 resolver。

- 每个 RecipeManager／原生 generation 共用一个构建任务；查询只返回已发布结果或未就绪的临时空快照，不同步全表构建、不等待构建锁。临时空快照不写入 CACHE，因此不会伪装为 ready。
- 配方收集、转换、Ingredient/ItemStack/AE 编码、注册表访问、索引与发布均留在原 owner 线程，按 tick 推进；目标预算每次约 2ms，并有步骤和指纹条数上限。
- 仅已冻结的 recipeId、fingerprint 字符串与序号排序进入单守护线程。owner 使用 isDone/getNow 检查，无 join/get 等待。原生 build 方法保留供整合包既有 Mixin 注入，其同步指纹 pipeline 在新调度路径中不执行。
- 客户端等待配方事件、客户端标签事件、JEI runtime（安装时）及 5 tick 安静窗口，再推进构建。同一 RecipeManager 与连接的维度切换保留目录；不同连接不复用 ready。同步期间通知仍更新失效版本；构建中失效取消旧任务，发布前再次核对原生 generation。
- 失败保留错误状态，每 5 秒最多重试，总共 3 次；耗尽后日志明确失败，直到新的失效，不逐帧重试。
- 保留 encounter order、identity 去重时首个来源、recipeId 字符串后 fingerprint 的最终排序，以及原生各索引与 resolver。
