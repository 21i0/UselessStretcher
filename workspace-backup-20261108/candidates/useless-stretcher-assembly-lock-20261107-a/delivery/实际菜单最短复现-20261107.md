# 总成担架快照：最短实际菜单复现

适用候选：`1.21.1-1.6.4-catalog-P4-assembly-lock`；本体按实际 `2.4.6.2` 字节码核对。以下为操作说明，本文件作者没有启动 MC、执行这些游戏命令、重跑 184 项测试或改动测试实例/JAR。

## 1. 准备物品和三个独立方块

在独立存档副本管理员聊天执行：

```mcfunction
/give @s useless_stretcher:omniversal_myriad 2
/give @s useless_stretcher:useless_stretcher 2
/give @s useless_mod:me_pattern_assembly 1
```

两个新万物之块分别手动放置为 A、B，总成为 T，记下坐标。用新空白物品放置 A/B；带数据的中键复制可能让两块共享同一源库，不能用来建立独立对照。

**本项菜单测试只需单独放置总成，不要求成型、供电或 AE 网络。** 空手右键 T 即可打开菜单，使用第一页第一个样板槽（底层 Slot 0）。未成型不影响本轮安装/拒绝交换检查；此最简布局不能验证 AE 配方发布或机器生产。

## 2. 建立两本不同的真实样板库

1. 右键 A → 搜索 `minecraft:furnace`（也可搜“熔炉”）→ 点具体机器行右侧的“获取”按钮。等待获取进度结束。左侧模具勾选与获取样板独立，不需要点“全部获取”。
2. 右键 B → 搜索 `minecraft:smoker`（烟熏炉）→ 点具体行右侧“获取”，等待结束。若此整包未提供该行，换为目录中实际存在的另一台机器，例如 `minecraft:crafting_table`，并记录实际选择。
3. 第一副担架 S_A 持在手上，Shift+右键 A；第二副 S_B 同样绑定 B。绑定提示有样板总数。分别持担架右键空气打开“样板仓库”，记录页数/若干输出标记和截图。A 可用铁锭或金锭作标记，B 可用食物或木板；以整包实际配方为准。确认两库非空且内容有区别后再继续。
4. 把 S_A/S_B 分开放在明确的背包格子。正常打开仓库即可查看，不用给担架伪造 pattern_ref 或给空 processing_pattern 充当真实样板。

## 3. 安装快照，再修改源库

1. 空手右键 T，把 S_A **从玩家背包拿起并放进总成 GUI 第一个样板槽**，关闭再重开确认仍在。持担架直接右键 T 是旧的“批量送入独立样板”操作，不能代替这一步。
2. 如需精确比较在槽 UUID，按第 6 节保存一次 T 的外置库存记录，记作安装 UUID U0。它应不同于 A 的 PatternRef，且担架 `pattern_ref == assembly_snapshot_ref`。
3. 回 A 的界面，获取另一机器的样板（例如烟熏炉），再点熔炉行的“移除”；也可最后点顶部“清空样板”测试源库全清。等待任务结束。S_B 的仓库应仍是 B 原库。
4. 暂时保留 T 内的 S_A，继续下面的交换拒绝检查。最后取出时，S_A 的仓库应仍显示安装前 A 的样板，原先铁/金等标记保留；不能变成更新后的 A、空库或 B。

## 4. 准备一张普通 AE 编码样板

使用现有 AE 样板编码终端，编码一张简单原版配方，例如橡木原木 → 木板。若没有终端，可管理员获取以下物品后搭一个小型供电网络（能量元件接线缆，终端装在线缆上）：

```mcfunction
/give @s ae2:creative_energy_cell 1
/give @s ae2:fluix_glass_cable 4
/give @s ae2:pattern_encoding_terminal 1
/give @s ae2:blank_pattern 4
/give @s minecraft:oak_log 1
```

在终端选择合成样板模式，放入空白样板，设置原木 → 木板并编码，取出编码成品。**测试用的是已经编码的样板，不是空白样板。** 也可用已有正常编码的普通处理样板。

## 5. 鼠标/热栏交换与正常取出

管理员准备完后切 `/gamemode survival`，按普通生存容器操作，避免创造物品栏的克隆干扰计数。T 中第一个槽仍应有 S_A。

1. **另一副担架覆盖：** 光标拿起 S_B，左键点击 T 的 S_A 槽。应拒绝交换：S_B 留在光标，S_A 留槽。把 S_B 放回玩家背包。
2. **普通样板鼠标交换：** 光标拿起一张已编码样板，左键点同一槽。应拒绝交换，原担架与光标样板的种类/数量均不变。
3. **普通样板数字键交换：** 清空光标，把该编码样板放在玩家快捷栏第 1 格；鼠标悬停总成的 S_A 槽，按数字键 `1`。应拒绝交换，快捷栏样板与槽内担架均保留，数量不变。
4. 关闭重开菜单确认服务端状态，必要时按第 6 节再保存一次：槽内 U0 应不变。不要只凭尚未重同步的一帧客户端显示判通过。
5. **正常取出：** 光标为空，左键拿出 S_A，放到玩家快捷栏并关闭菜单。T 槽变空，S_A 只有一副，普通样板和 S_B 都还在。持 S_A 右键空气检查第 3 节的安装前样板库；此时可读物品 UUID。
6. **空槽换装：** 取空后允许装入 S_B；也可把 S_A 重新装入。每次真实重新装入都会分叉新 UUID，这是预期行为，不能把重装后的 UUID 变化误判为覆盖。要记录旧 U0，请在重装前完成诊断。

## 6. 可用只读诊断与精确 UUID 取证

下列坐标占位符先替换为实际整数；`@s` 命令从测试玩家聊天执行，控制台改为玩家名。

```mcfunction
/data get block <AX> <AY> <AZ> PatternRef
/data get block <BX> <BY> <BZ> PatternRef
/data get entity @s SelectedItem.components."minecraft:custom_data"
/data get block <TX> <TY> <TZ> components."useless_mod:external_inventory_reference"
```

A/B 的 `PatternRef` 应不同；手持绑定前的 S_A/S_B 可见对应 `pattern_ref` 和 `pattern_dimension`。安装后正常取出的 S_A 应有 `pattern_ref`、`assembly_snapshot_ref`、`assembly_snapshot_dimension`；前两者相同，且不同于源 A/B 的 UUID。

**本体 2.4.6.2 的总成库存已外置。** `/data get block T` 不会直接给出 `Patterns.Items` 中的担架；上述 external_inventory_reference 的 `id` 是总成外置库存 UUID，不是担架快照 UUID。候选没有新增 dump/setup 管理命令。

要在不取出/重装的前提下精确核对 U0，可在“刚装入”和“源修改/交换尝试后”各执行一次 `/save-all flush`，每次完成后只复制相关 dat 到不同证据文件名，再用只读 NBT 工具检查副本（不修改活存档）。该命令会保存世界，放在 JEI 性能测量完成后执行。

本体外置引用 `kind=pattern_assembly`，`id` 用 UUID int-array 编码；转换为通常 UUID 字符串后，对应文件固定在主世界：

```text
<世界根>/data/useless_mod_inventory_pattern_assembly_<外置UUID>.dat
data.Inventory.Items[{Slot:0}].components."minecraft:custom_data".pattern_ref
data.Inventory.Items[{Slot:0}].components."minecraft:custom_data".assembly_snapshot_ref
```

两次副本中这两项均应为同一个 U0。即使 T 在其它维度，外置库存文件也在上述主世界 data 目录。

样板库本身是 `<源维度数据目录>/data/useless_stretcher_patterns.dat`（此流程在主世界，故为世界根/data）。格式 3 的 `data.entries` 以 `id` → `state` 引用 `data.states`；比较 U0 指向的完整状态/解码样板有序内容，而不是比较整个 dat 哈希或 state 数字（源库修改会改变整个文件，状态保存索引也可能变）。该对照能验证快照内容未变；只看 UUID 未变不足以证明内容未同步。

升级测试沿用完整存档副本：格式 3 不能安全回退给旧 1.6.3；回退恢复升级前完整备份。所有结论分开记“真实菜单”“源库隔离”“精确 UUID/库内容”“AE 发布/生产”，未测项保留未测。
